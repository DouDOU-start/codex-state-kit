## 登录

| 现象 | 处理 |
| --- | --- |
| 浏览器没有打开 | 点击「打开页面」，或切换授权码登录 |
| 回调端口被占用 | 结束其他进行中的登录；两个端口都不可用时使用授权码方式 |
| 授权成功后应用仍等待 | 确认授权来自本次登录窗口；检查会话是否已取消、超时或切换目录，再重新登录 |
| 登录成功但账号未更新 | 确认应用和 Codex 使用同一配置目录，并检查文件写入错误 |
| 只有 API Key，无法自动接入 | 当前自动接入要求 ChatGPT 登录 |

回调端口优先为 `1455`，备用为 `1457`。应用不会关闭其他程序来抢占端口。

## 网络

| 现象 | 处理 |
| --- | --- |
| 手动代理连不上 | 检查 URL 中的用户名、密码、端口和特殊字符编码；只开了 Clash 系统代理时，确认「经系统代理连接手动代理」已开启 |
| 订阅节点连接失败 | 检查订阅地址能否访问，或换一个节点 |
| HTTP 401 | 检查账号授权，必要时重新登录该账号 |
| HTTP 403 | 检查模型和网络出口 |
| `server_is_overloaded` / `server_error` | 查看上游错误并稍后重试 |
| 使用记录出现「已降级」或「疑似降智」 | 点击标记查看判定依据；「已降级」表示上游 `openai-model` 与请求模型不一致 |

## 接入与恢复

**已接入但没有请求记录**

确认 Codex 使用相同配置目录，重启客户端加载路由。使用自定义模型提供方时，其独立 `base_url` 可能绕过本应用。界面只保留最近 80 条请求记录。

**启动时报监听地址占用**

正式版默认使用 `127.0.0.1:8787`，开发版使用 `8788`。检查是否已有应用实例占用端口，或退出应用后修改设置文件中的 `proxy_listen`。

**异常退出后 Codex 无法连接**

重新启动 State Kit，再正常退出，让应用恢复路由。如果仍失败，先备份 `config.toml`，对照路由恢复记录还原原值；不要将其他提供方配置一并删除。完成后重启 Codex。

文件路径见[配置与自动接入](config.md)。仍无法解决时，按下方[问题报告](#问题报告)提供复现信息。

## 问题报告

建议提供：应用版本、系统版本、出站线路类型、操作步骤、期望结果和实际错误。日志保留时间、请求路径、状态码等必要信息即可。

提交前移除账号标识、认证头和代理密码。不要直接上传 `auth.json`。构建与检查命令见[开发与打包](development.md)。
