# 常见问题

[返回首页](../README.md)

## 登录

| 现象 | 处理 |
| --- | --- |
| 浏览器没有打开 | 点击「打开页面」，或切换授权码登录 |
| 回调端口被占用 | 结束其他进行中的登录；两个端口都不可用时使用授权码方式 |
| 授权成功后应用仍等待 | 确认授权来自本次登录窗口；检查会话是否已取消、超时或切换目录，再重新登录 |
| 登录成功但账号未更新 | 确认应用和 Codex 使用同一配置目录，并检查文件写入错误 |
| 只有 API Key，无法自动接入 | 当前自动接入要求 ChatGPT 登录 |

回调端口优先为 `1455`，备用为 `1457`。应用不会关闭其他程序来抢占端口。

## 网络与 Token

| 现象 | 处理 |
| --- | --- |
| WARP 一直准备中或重试 | 查看网络和 `warp.log`；可切换已知可用的手动代理 |
| 手动代理认证失败 | 检查 URL 中的用户名、密码、端口和特殊字符编码 |
| 等待 Token | 先确认 ChatGPT 登录和出站代理，再查看获取错误 |
| HTTP 401 | 检查账号授权；票据获取会按账号全局冷却 5 分钟 |
| HTTP 403 | 检查对应模型和网络出口；只冷却该模型 30 秒，其他模型仍会继续获取 |
| `server_is_overloaded` / `server_error` | 查看上游错误并稍后重试；已有 Token 也不能保证请求成功 |
| Token 有年龄但显示可用 | 采到后 30 秒会再采一张；超过 240 秒不再注入业务请求。若年龄明显异常，检查系统时间与获取日志 |

需要重新获取 Turn-State 时，可切换出站模式再切回，应用会清空缓存并重新获取。单纯重启会尝试恢复磁盘缓存，不一定触发重新获取。

## 接入与恢复

**已接入但没有请求记录**

确认 Codex 使用相同配置目录，重启客户端加载路由。使用自定义模型提供方时，其独立 `base_url` 可能绕过本应用。界面只保留最近 80 条请求记录。

**启动时报监听地址占用**

正式版默认使用 `127.0.0.1:8787`，开发版使用 `8788`。检查是否已有应用实例占用端口，或退出应用后修改设置文件中的 `proxy_listen`。

**异常退出后 Codex 无法连接**

重新启动 State Kit，再正常退出，让应用恢复路由。如果仍失败，先备份 `config.toml`，对照路由恢复记录还原原值；不要将其他提供方配置一并删除。完成后重启 Codex。

文件路径见[配置与自动接入](config.md)。仍无法解决时，按[问题报告要求](turn-state-sop.md)提供复现信息。
