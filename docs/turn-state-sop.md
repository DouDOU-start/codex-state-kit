# 维护与验收

[返回首页](../README.md)

本页用于验证当前版本。实际处理规则见[Turn-State 机制](turn-state-notes.md)。

## 桌面端验收

| 检查项 | 预期结果 |
| --- | --- |
| 启动窗口 | 默认 900 × 680，不能缩小到此尺寸以下 |
| 默认登录 | 选中浏览器回调，授权码方式仍可选 |
| 登录取消或目录切换 | 旧会话结束，后续回调不能写入凭据 |
| 自动接入 | 监听就绪且已有 ChatGPT 登录后更新路由 |
| 内置 WARP | 自动连接；切回手动模式后停止内核 |
| 工作目录变更 | 恢复旧目录路由，加载新目录账号与配置 |
| 正常退出 | 恢复原路由，保留登录文件 |
| GitHub 与版本 | 顶部仓库链接可用；开发显示 `dev`，安装包显示版本 |
| 配置兼容 | 接入期间原有 `service_tier` 保持不变；退出后仍恢复原值 |

使用专门的测试目录和测试账号验证真实登录与路由操作，避免多个实例管理同一配置目录。

## 转发验收

1. 启动应用，确认本机代理已监听并完成接入。
2. 在 Codex 发起请求，点击页面顶部「网络日志」，确认出现业务请求记录。
3. 有缓存时，分别检查新一轮首包（未携带也应补上规范票据，请求体不能出现 `previous_response_id`）、同轮续跑未携带（应补上规范票据）与已携带（应替换）的请求。
4. 确认后续 HTTP 请求显示正确模型、代理线路、TCP peer 和 Turn-State 替换长度。
5. 在一条进行中的 SSE 请求上确认日志显示响应头、当前静默和块数；完成后显示流总耗时、总字节与最大静默。取消请求时应显示“下游已取消”。
6. 同网策略下确认业务请求与 Token 获取走同一条出站代理（手动为 `routeKind=manual_proxy`，WARP 为 `embedded_warp`）。分路策略下配置上游转发代理后确认 `routeKind=explicit_proxy` 且 TCP peer 指向代理；清空后确认显示系统默认网络。
7. 填写强制绑定模型后，用其他模型 ID 发起请求，确认上游请求体和网络日志中的请求模型都是绑定值；清空后恢复按下游原模型转发。
8. 退出应用并重启 Codex，确认路由恢复且内存日志已清空。

## Token 获取验收

1. 对 `gpt-6-astra` 发起业务请求，使模型进入活跃列表。
2. 在网络日志中确认每次只有一条 `token_fetch` 在途，请求间隔不短于 6 秒。
3. 确认探针使用 HTTP/1.1，HTTP 非 200、312、错误前缀和不可解析票据均不会显示为可用。
4. 默认「跨模型复用 292」：任一模型命中后，所有 292 模型（含新增模型）直接复用，不再逐模型打票；共享票超过 35 分钟时只预取一张，超过 40 分钟不可再注入。切到「按模型独立」后确认缺票模型分别获取；切回共享后确认无需重新登录或清空原有缓存。
5. 有可用 292 时，下游未携带 State 的请求应显示「已补上 State」，已携带的请求仍按模型替换。
6. 模拟一个模型返回 403，确认该模型冷却 30 秒且其他模型仍继续获取；401、429/503 和连接失败仍按账号或线路全局退避。
7. 模拟业务响应返回 312，共享策略下确认所有旧 292 被清除并重新单发获取，旧策略下只清除对应模型票据；切换账号时确认旧账号票据不会与新账号鉴权组合发送。

“已接入”“Token 可用”和 HTTP 200 各自只表示对应状态，不能单独证明响应质量提升或彻底解决过载。不要用单题答案作为唯一验收标准。

## 问题报告

建议提供：应用版本、系统版本、代理模式、操作步骤、期望结果和实际错误。日志保留时间、请求路径、状态码等必要信息即可。

提交前移除账号标识、认证头、代理密码、Token 和 WARP 私钥。不要直接上传 `auth.json`、Token 缓存或 WARP `config.json`。

常见处理方式见[常见问题](troubleshooting.md)，构建与检查命令见[开发与打包](development.md)。
