# ChatGPT 登录

[返回首页](../README.md)

## 选择登录方式

| 方式 | 操作 |
| --- | --- |
| **浏览器回调（默认）** | 点击登录，在系统浏览器完成授权，应用自动同步结果 |
| **授权码登录** | 切换方式，打开验证页并输入应用显示的代码 |
| **Refresh Token** | 粘贴 RT；应用向官方授权服务换取新凭据，并保存服务端返回的轮换 RT |
| **Access Token** | 粘贴可解析的 Codex JWT；按外部 Token 模式接入，过期后需重新导入 |

已有账号时可点击「重新登录」。浏览器未自动打开时，使用「打开页面」重试；回调不可用时可改用授权码登录。RT 模式使用 Codex 官方 Client ID。

成功后，凭据写入当前 Codex 工作目录的 `auth.json`，随后自动接入。RT 会保存为可刷新登录凭据；AT 不含刷新能力。取消、授权失败或无效 Token 不会替换已有登录信息。退出应用只恢复路由，不退出 ChatGPT 账号。

## 回调行为

实现参考 [OpenAI Codex 登录源码](https://github.com/openai/codex/blob/main/codex-rs/login/src/server.rs)，使用随机 `state` 和 PKCE S256 校验授权响应。

- 仅监听 `127.0.0.1`，优先端口 `1455`，占用时尝试 `1457`。
- 回调地址为 `http://localhost:<端口>/auth/callback`。
- 两个端口都不可用时提示错误，不会终止其他应用。
- 回调会话有效期为 15 分钟；授权码方式以服务端返回的有效期为准。
- 取消、超时、切换工作目录或退出应用会清理会话，阻止旧回调继续写入凭据。
- 界面和回调结果页不展示访问或刷新 Token。
- RT 换票请求禁止跟随 HTTP 重定向，错误信息不会回显提交的 Token。
- RT/AT 输入框使用密码类型；提交后清空成功导入的 Token，不写入应用日志。

登录文件采用 Codex 原生结构，包含 `auth_mode`、`tokens` 和 `last_refresh`。浏览器、授权码和 RT 使用可刷新 ChatGPT 登录模式；AT 使用 Codex 的 `chatgptAuthTokens` 外部 Token 模式。Codex 刷新同一账号并写回更新的 `last_refresh` 后，Kit 会把轮换后的 AT/RT 同步回独立登录文件；不同账号的凭据不会被合并。

## 验证范围

本机模拟服务测试覆盖授权交换、RT 轮换、AT 导入、回调校验、凭据保存、取消、超时和端口冲突。真实账号登录需要在桌面应用中完成；纯浏览器预览仅模拟状态，不执行真实授权或写入账号文件。

登录异常的处理见[常见问题](troubleshooting.md)。
