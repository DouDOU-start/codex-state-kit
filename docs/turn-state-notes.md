# Turn-State 机制

[返回首页](../README.md)

本文说明当前代码行为。早期关于 Token 池、每条请求消耗一个 Token、30 分钟自动失效的实验方案，已不适用于当前实现。

## 获取与缓存

应用使用当前工作目录中的 ChatGPT 凭据，通过所选出站代理向上游 `/responses` 发起轻量请求，从响应头读取 `x-codex-turn-state`。探针使用与 Codex TUI 自洽的 `User-Agent`、`originator`、`version`，每次生成新的 `session_id`，请求体为固定的 `ping/pong` 轻量交互。

- 每轮只选择一个需要刷新的模型，共享 292 时随机选择一个不在冷却中的模型取票；按模型独立时轮询。同一波内可并发探测：第一次 1 路，连续打不到则 2，最高 4；打到目标长度后回到 1。打满 4 路仍未命中则静置 60 秒，再从 1 路重来。
- 请求强制使用 HTTP/1.1、新连接和 `Connection: close`；认证信息不会跟随重定向。
- 探针会收下上游 `Set-Cookie` 里的 Cloudflare / 线路 cookie（`__oailb`、`__cflb`、`__cf_bm`、`_cfuvid`、`cf_clearance`、`cf_chl_*` 等），绑到该张票据上；后续探针和业务 `/responses` 回放这些 cookie，把请求粘在同一边缘。官方登录 / session cookie 不会收、不会回放、也不会写进日志。覆盖 Kit 鉴权时只剥掉非白名单 Cookie，线路 cookie 会留下。打到 `chatgpt.com` 时额外带官方工厂 cookie `oai-chat-psp=true`。
- 只有 HTTP 200 下长度精确匹配该模型请求开始时绑定长度、前缀正确、时间戳可解析且未超过预取年龄的候选值才会入池；312、未来时间戳和其他长度仅记录后拒绝。
- Token 按来源模型分别缓存并保留来源，内存与本地文件同步，启动时尝试恢复；注入与预取遵循下述复用策略。
- 未命中目标长度时 6 秒后按 1→2→4 加倍再打；打满 4 路仍未命中则静置 60 秒，并发回到 1。连接失败仍按 30 秒退避。429/503 按全局线路退避 30 秒且不加并发，401 按账号全局冷却 5 分钟；403 只让对应模型冷却 30 秒。有可用票据时约每 30 秒巡检。
- 292 与探针 `Set-Cookie` 线路 cookie 成套入池、成套注入。采到后暂停 30 秒再采下一张，持续刷新凭据包；超过 240 秒不再注入。预取失败期间仍可使用尚未到 240 秒的旧包。
- 切换工作目录、出站地址、出站模式或上游配置等会清空缓存并重新获取。

获取成功必须同时满足 HTTP 200、响应头票据合法且匹配该模型当前绑定长度。探测使用账号授权发起真实请求，会消耗上游请求资源，不应视为无成本的本地检查。

## Token 复用策略

顶部 Token 卡片可切换并自动保存，配置字段为 `token_reuse_policy`。新安装和没有该字段的旧配置默认使用 `shared_292`。

| 策略 | 取票、注入和刷新 |
| --- | --- |
| 跨模型复用 292 `shared_292`（默认） | 同账号任一模型拿到精确 292 字节的有效票据后，目标长度为 292 的所有模型共用最新一张；新增模型也无需单独取票。只有共享票缺失或满 30 秒才再打，不会因为还有模型没有自己的缓存而重复打票。 |
| 按模型独立 `per_model`（旧策略） | 各模型分别缓存、获取、替换和续期，不借用其他模型的票据。 |

- 共享限定在同一个已识别的 ChatGPT 账号内；切换账号清空旧池，未知归属的旧缓存不会共享。
- 332、312 及其他长度不参与跨模型共享；显式绑定非 292 的模型仍独立取票，不会修改其他模型的默认绑定。
- 凭据包固定 240 秒新鲜窗口、采到后 30 秒再采，页面不再提供过期/预取时间配置。预取失败时仍可复用尚未过期的包。打新票直接使用当前登录文件里的 AT，不会先用 RT 换票。Token 卡片上的「重新获取」会立刻打一张新票，绕过后台冷却；即使已暂停自动获取，这次点击仍会取票，暂停状态保持不变。
- 切换策略保留各来源模型原有缓存，不复制共享票到其他模型；切回旧策略后缺票模型才恢复独立获取。设置保存后立即生效并在重启后恢复。
- 业务响应返回 312 时不入库、不覆盖、不清池；当前凭据包继续用到 240 秒，或等到采到新的 292 再整包替换。
- 页面显示共享来源模型，其他模型的实际采集池、分布统计不伪造。

跨模型复用是本项目可切换的实验策略，不是上游兼容性或模型质量保证；遇到兼容问题可切回按模型独立。

## 请求处理

| 流量 | 当前规则 |
| --- | --- |
| HTTP `POST`，路径包含 `/responses` | 默认按复用策略使用同账号的有效缓存：新一轮首包补上规范票据并包装成探针同轮第二包；同轮续跑（带 `previous_response_id` 或 tool output）只改请求头，不改 body |
| HTTP 客户端未携带 Turn-State | 探针当作该轮第一包。新一轮首包写入 `x-codex-turn-state` 和 `client_metadata`，并去掉 `previous_response_id`。同轮续跑即使未携带 State 也只改请求头，保留客户端 body |
| WebSocket 升级请求 | 返回 426，让 Codex 客户端回退到 HTTP SSE |
| 上游业务响应 | 不进入本地票据池；返回 312 时保留当前凭据包，不唤醒重打 |

缓存会重复使用，不会按请求消耗；代理层仍会按 HTTP 转发要求处理连接相关头。

主页面的「State 处理策略」自动保存到配置，旧配置默认使用 `preserve`：

| 策略 | 行为 |
| --- | --- |
| 无可用凭证时保留原值 `preserve` | 新一轮首包未携带则补上并包装为同轮第二包；同轮续跑只改请求头。没有匹配缓存或模型无法识别时保留客户端原值。Kit 切换请求账号后仍会移除旧账号 state。 |
| 无可用凭证时持续等待 `wait` | 没有匹配缓存则等待后台按复用策略取得同账号的有效凭证。新一轮首包再包装为同轮第二包；同轮续跑只改请求头。客户端断开会取消等待，不会之后补发。 |
| 无可用凭证时剥离 `strip` | 新一轮首包未携带则补上并包装为同轮第二包；同轮续跑只改请求头。没有匹配缓存或模型无法识别时删除请求中的 state。 |
| 不替换 `passthrough` | 始终原样保留客户端 state，有有效缓存也不替换、不补上、不按账号变化删除 state。 |
| 全部剥离 `strip_all` | 所有业务请求发出前均删除 state，包括存在有效缓存的情况以及 `/models` 等其他路径。 |

前三种策略只注入探针入池的规范 Fernet 票据（`gAAAAA` 前缀、可解析时间戳、非 312）。官方约定每一轮第一包不能带 turn-state；Kit 用探针充当第一包，新一轮首包包装成同轮第二包（请求头 + `client_metadata`，并去掉 `previous_response_id`）。同轮续跑只改请求头，body 原样转发，不依赖客户端是否回带 State。后两种仅控制 state，账号认证仍遵循 Kit 的登录转发规则；所有策略均保持上游响应中的 state 原样返回，后台凭证获取继续运行。

等待不会绕过后台获取的冷却或单发调度，不会使用其他账号或已过期票据；只有共享策略下的同账号 292 允许跨模型。等待策略下，`POST /responses` 请求明确携带的账号 ID 与当前登录账号不同时，即使存在缓存或未携带 State，也立即返回 409「账号凭据不匹配」，不等待、不转发。同一账号的 Access Token 不同（例如 Kit 或 Codex 刚换过 AT）不算冲突，Kit 仍可覆盖鉴权头后继续等待或转发。未显式携带账号并由 Kit 补齐的请求也不算冲突。模型无法识别时返回 422；账号无法识别，或等待期间登录账号、线路、策略发生变化时返回 409，请求不会发往业务上游。修改绑定长度后继续等待当前绑定匹配的凭证。尚在等待凭证的请求不计入已发往上游的并发数和 RPM。

## 当前边界

- **首包包装为第二包，续跑只改头**：官方客户端每一轮新建 `ModelClientSession`，首包不带 turn-state。Kit 把探针当作第一包；新一轮首包写入请求头和 `client_metadata`，并去掉 `previous_response_id`。同轮续跑（`previous_response_id` 或 tool output）只换请求头，不改 body。已携带但无法识别模型时按所选策略保留、剥离或拒绝等待。
- **账号快照保持一致**：每个业务请求使用同一份凭据快照完成票据池账号校验和 Kit 鉴权覆盖；客户端原头与当前官方账号不一致时不注入缓存票据。
- **业务响应不进入票池**：真实业务响应中的 Turn-State 只用于日志，不会覆盖后台探针取得的模型票据。
- **代理 URL 不做会话改写**：每次探针使用新 client 和新连接；动态住宅代理是否更换出口由代理供应商决定。
- **长度是项目筛选规则**：界面中的“292”“312/降智”是项目标签，不是模型能力或计算档位的官方指标。
- **线路 Cookie 跟票据走**：探针拿到的 `__oailb` / `__cflb` 等与那张 292 一起缓存和回放；过期后不再发送。不读取、不注入浏览器登录 cookie。

本工具以缓解使用问题为目标，不改变账号套餐、配额或模型本身，也不保证消除上游过载。历史实验中的地区、长度和单题回答差异不足以证明模型能力变化，不能作为稳定效果承诺。
