# 网络路由日志

[返回首页](../README.md)

主界面不直接铺开请求日志。点击页面底部的「网络日志」可查看当前路径和最近请求。

## 路径摘要

日志窗口分别显示 Token 获取和业务请求路径：

- **Token 获取**：State Kit 通过内置 WARP 或手动代理访问 Codex 上游。WARP 行显示最近一次验证到的出口 IP 和地区。
- **业务请求**：Codex 先连接本机代理。默认同网策略下，再走与 Token 获取相同的出站代理；分路策略下，再通过独立的上游转发代理或系统默认网络访问 Codex 上游。留空上游转发代理时，进程仍可能受系统或环境代理影响，因此界面不会把该模式标成直连。

同网策略下两条线路共用当前出站代理。分路策略下互不继承，需要分别填写。`socks5://` 在实际请求中会转换为 `socks5h://`，使上游域名解析也通过 SOCKS 代理完成。代理 URL 含 `{session}` 时，Token 获取记录显示当次探测 session；业务请求在拿到稳定 292 后显示绑定 session。

## 请求字段

Token 获取和业务请求都会形成逐次记录，窗口里分成两组：上面是业务请求，下面是 Token 获取。复制日志也按这两组导出。每条记录包含请求时间、用途、方法、路径、模型、传输协议、配置代理、目标 origin、最终响应 origin、TCP peer、HTTP 版本、Turn-State 动作与长度、请求体大小、编码、状态码和收到响应头的耗时。

Turn-State 列同时记录请求开始时的策略（无票保留、无票等待、无票剥离、不替换、全部剥离）及实际动作，切换策略不会改变已有日志。客户端已带 State 时显示「已替换」；未带但补上规范票据时显示「已补上 State」。等待成功显示「等待后已替换」或「等待后已补上 State」；无法识别模型、账号或等待期间配置改变会记录明确的未转发原因。

请求列同时显示「请求模型」和「上游响应」。参考 [sub2api 的模型观察逻辑](https://github.com/Wei-Shaw/sub2api/blob/main/backend/internal/service/upstream_response_model.go)，从 SSE / JSON 的 `response.model` 或顶层 `model` 提取上游声明；先展示首个有效值，完成、失败等结束事件中的有效值优先覆盖。只读取响应元数据，不从生成文本或工具参数中寻找模型名；转发内容不作修改。

两个完整名称相同时显示「模型一致」，不同时橙色标记「模型不一致」，版本后缀也参与比较。没有请求模型或尚未读到响应模型时显示「无法比较」，不会用请求模型填充响应模型。Token 探针只读取响应头，显示「未读取（仅响应头）」。这些字段同步包含在复制日志中；旧日志不会补全。这里记录的是上游声明的名称，不能单凭此字段证明实际运行的模型。

业务请求还显示以下性能数据，并同步包含在「复制日志」中：

- **首字**：请求进入本机代理到收到首个非空文本、拒绝文本、工具参数/输入或图片分片事件的时间。参考 [sub2api 的真实可见输出口径](https://github.com/Wei-Shaw/sub2api/blob/main/frontend/src/i18n/locales/zh/admin/settings.ts)，响应头、心跳、`response.created` 和空 delta 不计入首字；推理等待计入首字延迟。
- **总耗时**：请求进入代理到响应体读完或中断的时间，包括上传请求、等待上游和流式传输。传输过程中显示「进行中」，首字到达后会更新同一条日志。由于保持下游背压，慢客户端也可能增加此耗时。
- **tok/s**：上游 usage 报告的输出 token 数 ÷（总耗时 − 首字延迟），在正常结束且统计数据完整时显示。输出 token 数直接沿用上游口径，可能包含 reasoning tokens；不通过字符数或网络分块数量估算 token。

没有可识别的可见输出、usage、有效生成时间，或发生流错误/客户端中断时，相应指标显示「—」。非流式 JSON 可以读取 usage，但不推算首字和 tok/s。zstd、gzip、deflate 响应会在统计旁路增量解压，原始压缩字节和响应头仍原样转发，不改变上游请求。未知编码、叠加编码或解压失败时跳过内容统计。SSE 单个事件或非流式 JSON 的统计读取上限为 128 KiB，zstd 解码窗口上限为 8 MiB；超过事件上限会跳过该事件/响应的内容统计，但继续原样转发。结果/性能列单独标明响应压缩编码；Turn-State 列的编码描述请求体，两者可能不同。

Token 获取只需要响应头中的 state，拿到响应头后就结束探测，因此仍显示响应头耗时，不等待模型生成。HTTP 200 后的流异常通过 `response_body`、`response_failed`、`response_incomplete`、`stream_idle` 或 `client_cancelled` 标记，避免只看状态码误判请求已成功完成。业务 SSE 在已有数据块后静默约 90 秒、或响应头后一直没有正文约 180 秒时，会写入 `response.incomplete` 并断开，让 Codex 结束本轮并可以重试。

部分上游省略 `Content-Type`，此时按请求的 `Accept: text/event-stream` 继续解析 SSE。客户端在收到 `response.completed` 后停止读取属于正常完成，不标记 `client_cancelled`；尚未收到完成事件就断开的请求仍按中断记录。HTTP 200 只代表响应头状态，红色表示该请求还记录了流错误。

业务响应在收到响应头后继续记录流生命周期：等待首块、传输中、完成、读取错误或下游取消，以及首块/最后块/完成耗时、块数、字节数、当前静默时间和最大正文静默时间。最大正文静默涵盖响应头到首块、相邻响应块以及末块到结束之间的间隔。时间均从 State Kit 收到本机请求开始计算，因此“响应头耗时”和“流总耗时”是两个不同指标。正在传输的记录会随状态轮询更新。

收到响应头后以上游 `Content-Type` 为准判断是否为 SSE；明确的 JSON 等错误响应按普通 HTTP 记录。请求账号与票据池绑定账号不一致时，Turn-State 动作文案只显示账号变化，不展示票据池账号标识；请求本身的账号仍按下方数据边界记录。

Token 获取探针与业务转发按上游 ALPN 协商 HTTP 版本，同一代理地址复用连接；明文 HTTP 上游仍是 HTTP/1.1。默认跨模型共享 292，任一模型命中后停止其他模型重复获取，直到共享票需要预取；旧策略按各待刷新模型轮询。连续打不到时同一波可并发 2/4 路，每路仍是一条真实 `token_fetch`；401/429/503 不加并发。两波之间至少间隔 6 秒；打满 4 路仍未命中则静置 60 秒后从 1 路重来。

`TCP peer` 表示本次连接首先到达的网络地址：配置显式 HTTP / SOCKS 代理时通常是代理地址；使用系统默认网络时通常是上游地址或系统代理地址。它不是最终公网出口 IP。

日志最多保留 80 条，只存放在进程内存中，退出应用后清空。为避免并发探测或连续失败淹没业务记录，其中 Token 获取记录最多保留 48 条。点击「复制日志」可复制当前路径摘要和结构化记录。

排查卡住时另有一份落盘诊断日志：用户目录下的 `.codex-state-kit-diag.jsonl`（开发模式为 `.codex-state-kit-dev-diag.jsonl`）。按请求写入 `request` / `headers` / `first_token` / `chunk` / `finish` 和 `token_fetch`，只记票据指纹、线路 cookie 名、是否同轮续跑、SSE 事件类型和流进度，不写票面、cookie 值、请求体或生成文本。超过约 8 MB 会轮换成同名 `.1`。网络日志窗口会显示该路径。

## 数据边界

账号筛选和逐条日志展示邮箱，内部仍按 account ID 区分记录。邮箱随请求使用的登录信息一起记录，切换账号不会改变历史请求的邮箱。缺少邮箱时显示「邮箱未知」，无法识别账号时显示「账号未知」；复制日志也使用邮箱。

主页面的「当前账号请求」按转发时生效的 `ChatGPT-Account-ID` 分开统计，只展示当前登录账号的数据。当前并发从业务请求发往上游起，到响应结束、失败或取消止，包含等待响应头的时间；RPM 为滚动最近 60 秒发起的请求次数，失败请求也计入。自动 Token 探测与 WebSocket 回退握手不计入。计数独立于最近 80 条日志，长请求即使日志被淘汰仍计入并发；切换账号不会混合计数。这些是本进程观测到的业务流量，无法统计绕过本机代理的请求，退出应用后清空。页面随状态轮询约每 1.5 秒更新。

网络日志不保存 Authorization、Cookie、API key、代理用户名或密码、Turn-State 原值、请求体、响应体、响应块内容和 URL query。流生命周期只累加时间、块数与字节数。模型与路径会移除控制字符并限制长度。错误仅记录 `connect`、`timeout` 等类别，不复制完整上游错误内容。
