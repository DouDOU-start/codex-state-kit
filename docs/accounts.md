# 账号与登录

[返回首页](../README.md)

Kit 可以保存多个 ChatGPT 账号，一键切换。每个账号绑定自己的虚拟设备和出站线路，切换账号时一起换，避免多个账号共用同一台设备或同一个出口。

## 添加账号

在「Codex 接入」页点击「添加账号」，在弹窗里选择登录方式：

| 方式 | 操作 |
| --- | --- |
| **浏览器回调（默认）** | 点击「打开浏览器登录」，在系统浏览器完成授权，结果自动同步 |
| **授权码登录** | 点击「获取授权码」，打开验证页并输入弹窗中显示的代码 |
| **Refresh Token** | 粘贴 RT；Kit 向官方授权服务换取新凭据，并保存服务端返回的轮换 RT |
| **Access Token** | 粘贴可解析的 Codex JWT；按外部 Token 模式接入，不能自动刷新，过期后需重新导入 |

登录成功后弹窗自动关闭，账号加入列表并切换为当前账号。登录请求走当前出站线路；新账号分配一台独立的虚拟设备，并沿用当前出站线路。登录的账号已在列表里时不会重复添加，而是更新它保存的凭据，并换回它自己的虚拟设备和线路。取消、授权失败或无效 Token 不会替换已有登录信息。RT 模式使用 Codex 官方 Client ID。

## 重新授权

账号的授权过期（例如 RT 已失效或被轮换掉）后，在账号列表点该账号的钥匙图标；凭据已失效的账号直接显示「重新授权」按钮。弹窗与添加账号相同，登录后：

- 更新该账号保存的凭据，并切换为当前账号；
- 保留它原来的虚拟设备和出站线路；
- 登录请求走它自己的手动代理。绑定订阅节点的账号走当前线路，因为订阅内核同时承载正在进行的请求。

Access Token 账号默认打开 Access Token 方式，粘贴新的 Token 即可。浏览器里登录的如果不是这个账号，会提示并作为另一个账号保存。

## 切换与管理

- **切换**：在账号列表点「切换」，或在系统托盘菜单里直接选账号。切换立即生效，无需重启 Codex；进行中的请求仍按发出时的账号完成和记账。
- **环境绑定**：切换时 Kit 同时换上该账号保存的虚拟设备和出站线路。账号第一次被切换到时，会分配一台新的虚拟设备并沿用当前线路；之后在「出站网络」或「虚拟设备」里的修改都记在当前账号下。
- **显示名**：列表、托盘和各处的账号筛选都显示账号邮箱，没有邮箱时显示账号 ID。
- **删除**：正在使用的账号不能删除。删除会同时删掉该账号保存的凭据、虚拟设备和线路绑定，之后需要重新登录。
- **凭据失效**：保存的凭据已失效的账号会标出「凭据失效，请重新授权」，不能切换过去，点「重新授权」即可恢复。只有 Access Token 的账号标为「不可自动刷新」。

## 登录文件

| 文件（位于 Codex 工作目录） | 用途 |
| --- | --- |
| `auth.codex-state-kit.json` | Kit 当前使用的登录，每次转发请求都从这里读取凭据 |
| `accounts.codex-state-kit.json` | 已保存的账号：各自的登录、虚拟设备和出站线路 |
| `auth.json` | 接入期间被 Kit 的当前登录覆盖，让 Codex 客户端也使用同一账号 |
| `auth.json.codex-state-kit.bak` | 接入前的官方 `auth.json` 备份，正常退出时用它还原 |

登录文件采用 Codex 原生结构，包含 `auth_mode`、`tokens` 和 `last_refresh`。浏览器、授权码和 RT 使用可刷新的 ChatGPT 登录模式；AT 使用 Codex 的 `chatgptAuthTokens` 外部 Token 模式。Codex 刷新同一账号并写回更新的 `last_refresh` 后，Kit 会把轮换后的 AT/RT 同步回自己的登录文件；每次切换账号或新登录前，也会先把当前账号的最新凭据写回账号列表，不同账号的凭据不会被合并。

退出应用会恢复原来的 `auth.json` 与路由，不会删除已保存的账号。

## 回调行为

实现参考 [OpenAI Codex 登录源码](https://github.com/openai/codex/blob/main/codex-rs/login/src/server.rs)，使用随机 `state` 和 PKCE S256 校验授权响应。

- 仅监听 `127.0.0.1`，优先端口 `1455`，占用时尝试 `1457`。
- 回调地址为 `http://localhost:<端口>/auth/callback`。
- 两个端口都不可用时提示错误，不会终止其他应用。
- 回调会话有效期为 15 分钟；授权码方式以服务端返回的有效期为准。
- 取消、超时、切换工作目录或退出应用会清理会话，阻止旧回调继续写入凭据。
- 界面和回调结果页不展示访问或刷新 Token。
- RT 换取请求禁止跟随 HTTP 重定向，错误信息不会回显提交的 Token。
- RT/AT 输入框使用密码类型；成功导入后清空，不写入应用日志。

## 验证范围

本机模拟服务测试覆盖授权交换、RT 轮换、AT 导入、回调校验、凭据保存、账号切换、取消、超时和端口冲突。真实账号登录需要在桌面应用中完成；纯浏览器预览仅模拟状态，不执行真实授权或写入账号文件。

登录异常的处理见[常见问题](troubleshooting.md)。
